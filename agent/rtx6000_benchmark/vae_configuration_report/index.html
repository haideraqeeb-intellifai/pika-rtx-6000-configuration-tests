Do more VAEs make this video faster?

Measured on one RTX PRO 6000, using the same 49.4-second podcast, ten independent chunks, two denoising steps and 24 fps. Model canvas: 736 × 1280, cropped to 720 × 1280 and exported at 1080 × 1920. Fixed chunk seeds: 9901–9910. Hardware: RTX PRO 6000 Blackwell Workstation Edition, 95.59 GiB usable device capacity.

What the tests found

The fastest new full-run setting was Overlap stages · 1 transformer / 1 VAE, averaging 248.4 seconds across 1 run(s). The previous paired-worker baseline averaged 252.2 seconds. The new setting changes measured throughput by +1.5%.

A transformer generates a chunk's latent representation. A VAE turns it into video frames. More copies share the same GPU's compute and memory bandwidth. The table below tests both the copy count and when each stage runs.

Practical choice and limits

Use one transformer feeding one VAE, with ordinary scheduling, as the provisional choice. GPU-encode conditioning once, release the encoder, and let these two stage workers overlap. It is the fastest observed setting here and uses about 39.6 GiB, compared with 72.1 GiB for the earlier paired combined workers. Differences of a few seconds need repeat confirmation.

Four VAEs plus MPS reduced the staged decoder phase from 98.2 to 83.2 seconds, but the complete video still took 251.9 seconds. One-VAE batching saved only about 3.4% of decoder-phase time. More copies helped that stage modestly; they did not produce the fastest complete-video result.

Repeat confirmation is pending GPU recovery. The 65/35 MPS resource-split attempt failed with a CUDA launch error and NVML reported GPU lost. All benchmark MPS clients/controllers exited; the reset command requires administrator credentials. The fault occurred during this configuration, but its root cause is not established. This setting is excluded and is not recommended.

What “valid” means here

Successful outputs passed complete video/audio decoding, frame-count, frame-rate and audio timing checks. All twelve successful new full-generation layouts produced identical decoded pixels; the batch-of-one replay matched too. Batch sizes two and four differed slightly (SSIM at 180 × 320: 0.998492 and 0.998115), which is technical similarity, not a human quality rating. Audio offsets are measured at 8 kHz. Join brightness changes screen for possible discontinuities; they do not establish seamless motion or lip synchronization. Review the videos below.

All chunks use the same portrait as first/last conditioning. They are independent; this is different from previous-last-frame chaining. Overlapping process calls do not prove simultaneous CUDA kernels. These are one-GPU measurements, with no eight-GPU speedup claim.
