Batch size two does not mean two chunks per video. It uses the five fixed chunks as [0,1] → [2,3] → [4]. VAE workers decode completed chunks while the transformer continues. Two transformer copies take independent chunks from the same five-chunk queue.

Batching was genuine: the five chunks used three sampler calls and six main transformer forwards, versus five calls and ten forwards without batching. Kernel resource measurements

@@NCU@@

Selected INT8 matrix kernels reached up to 94.9% SM throughput; another reached 90.3% DRAM throughput. Their roughly 16.7% warp occupancy does not imply that the remaining GPU capacity can run several additional copies efficiently. Register and shared-memory limits allow only one of these GEMM blocks per SM.

A specific fast-kernel tuning opportunity

The captured SageAttention3 launch uses 170 blocks on this 188-SM GPU. The installed fast-kernel source hard-codes 170. Each block requests 100,352 bytes (98 KiB) of shared memory, against 100 KiB per SM, leaving insufficient shared memory for a second copy of that block on the same SM. This limits how much two such kernels can overlap productively.

Changing the launch to account for the actual SM count is an untested tuning candidate, not a measured speedup. It could also reduce room for concurrent VAE work. The benchmark kept the existing fast kernel unchanged. Source and launch evidence.

Definitions and profiling limitations: NVIDIA Nsight Systems guide; NVIDIA Nsight Compute profiling guide. The initial thread-scoped NCU filter captured no kernels because inference runs in another thread; the successful capture uses process-scoped NVTX filtering. NCU replays selected isolated kernels and can serialize work; its times are not concurrent pipeline timings.

4. Fixed workload and fair comparison

@@METHOD@@

What is held constant

All layouts reuse byte-identical GPU-prepared conditioning, then release the text encoder. The transformer and VAE workers remain alive through the full warmup and three measured videos. Each worker owns its model copy. The existing fast VAE path retains its quantized projection cache on CPU and copies those projections to a request-local GPU cache for each decode; this is held constant across layouts. The memory table separately reports transformer and VAE residency accounting. MPS is enabled with the same 100% active-thread allowance. Dispatch queues permit stage overlap; each VAE decodes one chunk at a time.

Warmup and repetitions use the same fixed inputs. This is a resident replay benchmark, not a production service or a randomized cross-day experiment. Small differences should not be treated as a precise long-term gain.

Quality limitations

Frame/audio integrity, waveform timing, reproducibility and visual differences are checked. Those checks do not rate semantic quality, natural motion, lip synchronization or seam acceptability. Native first/last-image conditioning does not force exact endpoint pixels; export trims the native 243 frames to 240.
