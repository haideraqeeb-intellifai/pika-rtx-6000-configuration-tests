Is the parallel pipeline worth it?

Five 10-second chunks of Pika Flex fast mode, measured through the correctly timed final MP4. Three warmed full-video runs per configuration.

Decision

The parallel pipeline saves 12.87 seconds (5.8%), below Surya’s roughly 20% latency reduction bar. For this workload, the extra MPS, VAE worker and pipeline maintenance are not justified.

What changed?

A · simple: one resident transformer, one resident VAE, no MPS. One job runs five chunks serially, with no cross-chunk stage overlap.

B · parallel: one resident transformer, two resident VAE workers, MPS and cross-chunk transformer/VAE overlap.

Everything else matched: two-step fast path, prepared conditioning, independent original-image anchors, seeds 9901–9905, dimensions, audio and output encoding. The 49.408-second source audio received the same 0.592 seconds of trailing silence in both.

Why the gain is modest

Nsight Systems found 39.07 s of actual transformer/VAE GPU kernel overlap in B and zero in A. B kept SMs active more often, but overlapping work competed for the same GPU. Its measured end-to-end gain was only 12.87 s.

B’s host stage calls overlapped for 139.95 s; that is not the same as GPU kernel overlap. Existing Nsight Compute findings were reused; no profiler timing entered the A/B means.

Request and startup time

GPU conditioning preparation took 16.44 s. Adding this same measured phase gives resident request estimates of 239.59 s for A and 226.71 s for B.

These are phase sums, not separately timed end-to-end requests. Process setup averaged 5.45 s (A) and 5.60 s (B); lazy model loading happened in excluded full-video warmups, so a pure model-loading subphase was not isolated.

Verified output

All six final MP4s were byte-identical. Each has 1,200 delivered frames at 24 fps for 50 seconds, with 243 native frames generated per chunk and 240 exported. Frame timestamps, audio start and duration, and full decode were checked; lossless correction left compressed streams unchanged.

Open the 50-second MP4. One file represents all six byte-identical outputs.

Real-time factor: A 4.463×, B 4.205× (generation seconds / 50). Visual motion and lip sync remain available for human review.
